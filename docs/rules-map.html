五、程式化順序（避免「忘記沒做」）

  1. auto_exec.py — 把 T6.5 從模型手上拿走。 讀 position-flags / price-alerts / position-state，只吃前一收盤判定機械觸發（R23 線、用戶裁決線、R8 級距、SGOV 停泊、選擇權管理線），過五條件後用 Firstrade lib 下單、register-order、resolve-flag、shadow record 一氣呵成；模型只負責寫「為什麼」。這一步同時解 C5、C6、R16、R24、R17。風險最高也最值得——真錢單走 code 前先跑兩週 dry-run（只印不送）。
  2. position_guard 加四個檢查：R8+R23 累計賣出 % 對 30% runner 保底（C2）、R14 鎖住 R23 arm（C3）、樂透桶無停損單（R16）、閒置現金額與 SGOV 建議單（R24）。都是讀現有 state 就能算。
  3. 兩個 lint：telegram.txt 的 R27 檢查（認列桶行必含機械線）併進 crossday_check 的 hook；trade_ledger ingest 時對新倉首筆檢查 H10（>2% 自動標 bypass）。
  4. SessionStart hook：settings.json 目前只有 PostToolUse。加 journal_stub + review_due 到 SessionStart，互動 session 也不會漏 journal 和到期提醒（CLAUDE.md 寫的「SessionStart 自動 journal 偵測」實際上沒設）。
  5. thesis_ledger add 對 reentry-* 強制雙分支（R20），退役 R7。

判斷型的六條（R1/R2/R5/R6/R12/R13）刻意不程式化：它們的價值在「有沒有想清楚」，程式化只會變成打勾。對它們的紀律是影子帳——每次判斷都留一筆可計分的紀錄。
